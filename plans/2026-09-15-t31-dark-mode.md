# Dashboard Dark Mode (T31) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a light/dark toggle to the dashboard's shared header that switches every dashboard page, persists per-browser, and leaves the public `/s/[slug]` page untouched.

**Architecture:** Tailwind v4's CSS-based dark variant (`@custom-variant dark`), driven by a `data-theme` attribute on `<html>` instead of `prefers-color-scheme`, so the choice is explicit and user-controlled rather than OS-driven. A tiny `beforeInteractive` inline script in the root layout sets that attribute from `localStorage` before first paint, so there's no flash of the wrong theme. A `ThemeToggle` client component reads/writes the same `localStorage` key and lives in the dashboard header. Every dashboard page/component gets `dark:` variants added to its existing Tailwind color utility classes, following one fixed mapping table (Task 2) covering the full, real set of color classes already used in this codebase — confirmed by grep against the actual tree, not guessed.

**Tech Stack:** Tailwind CSS v4 (`@custom-variant`, confirmed against the installed v4.3.3's own current docs), `next/script` (`beforeInteractive`, confirmed against this repo's bundled Next.js 16 docs per `AGENTS.md`), plain `localStorage` — no new dependency.

**Spec:** `spec/plan.md`, Tech decisions (dark-mode bullet) + Tasks table row T31 — this plan implements that design exactly; read it alongside this plan.

## Global Constraints

- **Dashboard only.** `src/app/s/[slug]/**` is never touched — it keeps its own forced-black styling from T25 exactly as-is.
- **No new dependency** — Tailwind v4 supports this natively (`@custom-variant`); no `next-themes` or similar package.
- **Every retrofit step uses only the mapping table in Task 2** — no ad hoc new color choices per file, so the app stays visually consistent. If a file needs a pairing not in the table, add it to the table first (Task 2's own instruction), don't improvise one-off.
- **No test framework exists in this repo** — verification is real manual browser checks (toggle both ways, confirm legibility) per page, matching T29/T30's precedent.

- [ ] **Step 1: Replace the fixed-light block in `globals.css` with real light+dark tokens and the custom variant**

Replace the current `:root` block and the comment above it with:

```css
@import "tailwindcss";

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

/*
 * Light is the default (:root). Dark values apply only when [data-theme=dark]
 * is set on <html> by ThemeToggle.tsx / the pre-paint script in layout.tsx --
 * never by prefers-color-scheme, so the choice is explicit, not OS-driven.
 * `color-scheme` still flips with the theme so native form controls (inputs,
 * selects) stay legible in both -- this is the same login-field bug this
 * file's fixed-light setup originally existed to avoid, now solved for both
 * themes instead of by locking out dark mode entirely.
 */
:root {
  color-scheme: light;
  --background: #ffffff;
  --foreground: #171717;
}

[data-theme="dark"] {
  color-scheme: dark;
  --background: #0a0a0a;
  --foreground: #ededed;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);
}

body {
  background: var(--background);
  color: var(--foreground);
  font-family: Arial, Helvetica, sans-serif;
}
```

- [ ] **Step 3: Add the pre-paint theme script to the root layout**

In `src/app/layout.tsx`, add `import Script from "next/script";` and, as the first child inside `<body className="min-h-full flex flex-col">`, before `{children}`, add:

```tsx
<Script
  id="theme-init"
  strategy="beforeInteractive"
  dangerouslySetInnerHTML={{
    __html: `
      try {
        var t = localStorage.getItem("theme");
        if (t === "dark") document.documentElement.setAttribute("data-theme", "dark");
      } catch (e) {}
    `,
  }}
/>
```

(`beforeInteractive` scripts are always injected into `<head>` regardless of where they're placed in the tree, and must live in the root layout — confirmed against this repo's bundled Next.js docs, `node_modules/next/dist/docs/01-app/03-api-reference/02-components/script.md`.)

- [ ] **Step 4: Write the toggle component**

```tsx
"use client";

import { useEffect, useState } from "react";

export function ThemeToggle() {
  const [isDark, setIsDark] = useState(false);

  useEffect(() => {
    setIsDark(document.documentElement.getAttribute("data-theme") === "dark");
  }, []);

  function toggle() {
    const next = !isDark;
    setIsDark(next);
    document.documentElement.setAttribute("data-theme", next ? "dark" : "light");
    try {
      localStorage.setItem("theme", next ? "dark" : "light");
    } catch {
      // Private browsing / storage disabled -- theme just won't persist.
    }
  }

  return (
    <button
      type="button"
      onClick={toggle}
      aria-label={isDark ? "Switch to light mode" : "Switch to dark mode"}
      className="rounded border border-neutral-300 dark:border-neutral-600 px-2 py-1 text-xs font-medium text-neutral-600 dark:text-neutral-300 hover:text-neutral-900 dark:hover:text-neutral-100"
    >
      {isDark ? "Light mode" : "Dark mode"}
    </button>
  );
}
```

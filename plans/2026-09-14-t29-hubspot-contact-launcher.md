# HubSpot Contact-Record Launcher (T29) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a Securafy rep click a link on a real HubSpot Contact record that opens this app's New Package form in a new tab, prefilled with that contact's name and email.

**Architecture:** A small, standalone HubSpot developer-platform app (`hubspot-extension/`, its own npm project, not part of the Next.js app) with one Card UI extension on the Contact object. The card reads the record's own `firstname`/`lastname`/`email` and renders a link to `https://securafy-shock-and-awe.vercel.app/packages/new?prospect_name=...&prospect_email=...` — the URL-prefill on that page already shipped, so nothing in the Next.js app changes. Private distribution + static auth: installs only into Securafy's own portal, no OAuth server, no marketplace listing.

**Tech Stack:** HubSpot CLI (`@hubspot/cli`), HubSpot UI Extensions SDK (`@hubspot/ui-extensions`, `@hubspot/ui-extensions/crm`), React 18, TypeScript config only (component itself is plain `.jsx`, matching HubSpot's own generated boilerplate).

**Spec:** `spec/plan.md`, section "T29 HubSpot Contact-record launcher" (committed `2f73ffa`) — this plan implements that design exactly; read it alongside this plan.

## Global Constraints

- **Private distribution, static auth only** — no OAuth flow, no marketplace listing. Installs to a single portal.
- **Target portal: HubID `46124718`** (Securafy's real portal) — the HubSpot CLI's default account after auth, so commands below don't need `--account`.
- **Required scope: `crm.objects.contacts.read`** — nothing else. The card never writes to HubSpot.
- **Card reads only `firstname`, `lastname`, `email`** — no Company field in v1 (would need a second associated-object fetch; explicitly out of scope, see spec).
- **Target URL base: `https://securafy-shock-and-awe.vercel.app/packages/new`**, query params `prospect_name` and `prospect_email` exactly — these must match `searchParams` already read by [page.tsx](../src/app/(dashboard)/packages/new/page.tsx) (`prospect_name`, `prospect_company`, `prospect_email`). Do not change param names.
- **No changes anywhere under this repo's existing `src/`** — this feature is fully self-contained in a new `hubspot-extension/` folder with its own `package.json`/toolchain.
- **No automated test framework exists for HubSpot UI extensions** (none is documented by HubSpot, and this repo's own Next.js app has no test framework either — see its `CLAUDE.md`, "Test: TBD"). Every task below substitutes a real, concrete manual/CLI verification step for the automated-test steps this skill's template normally calls for. This is a deliberate, documented deviation, not a shortcut.
- **No new secrets in this repo.** The static auth access token HubSpot issues for the installed private app lives inside HubSpot's own Settings UI (revealed/rotated there), never written to a file in this repo.

- [ ] **Step 3: Write the card component**

Create/replace `hubspot-extension/src/app/cards/ShockAndAwe.jsx`:

```jsx
import React from "react";
import { hubspot, Text, Flex, Link } from "@hubspot/ui-extensions";
import { useCrmProperties } from "@hubspot/ui-extensions/crm";

// Base URL for the Online Shock-and-Awe portal's New Package form. Its
// prospect_name/prospect_email query-param prefill already shipped there
// (see spec/plan.md T29) — this card only needs to build the URL.
const SHOCK_AND_AWE_NEW_PACKAGE_URL =
  "https://securafy-shock-and-awe.vercel.app/packages/new";

// Manual query-string building (encodeURIComponent, a plain ECMAScript
// global) instead of URL/URLSearchParams: those are DOM/WebWorker-lib
// types not confirmed available in the UI-extension sandbox runtime,
// which HubSpot's own docs say has no real window/document/fetch.
function buildPackageUrl(properties) {
  const firstName = (properties.firstname ?? "").trim();
  const lastName = (properties.lastname ?? "").trim();
  const fullName = [firstName, lastName].filter(Boolean).join(" ");
  const email = (properties.email ?? "").trim();

  const params = [];
  if (fullName) params.push(`prospect_name=${encodeURIComponent(fullName)}`);
  if (email) params.push(`prospect_email=${encodeURIComponent(email)}`);

  return params.length
    ? `${SHOCK_AND_AWE_NEW_PACKAGE_URL}?${params.join("&")}`
    : SHOCK_AND_AWE_NEW_PACKAGE_URL;
}

const ShockAndAweCard = () => {
  const { properties, isLoading, error } = useCrmProperties([
    "firstname",
    "lastname",
    "email",
  ]);

  if (isLoading) {
    return <Text>Loading contact details…</Text>;
  }

  if (error) {
    return <Text>Couldn't load this contact's details: {error.message}</Text>;
  }

  const packageUrl = buildPackageUrl(properties);
  const hasEmail = Boolean(properties.email && properties.email.trim());

  return (
    <Flex direction="column" gap="medium">
      <Link href={{ url: packageUrl, external: true }} variant="primary">
        Send Shock-and-Awe Package
      </Link>
      {!hasEmail && (
        <Text>
          No email on file for this contact — you can still open the form
          and enter it manually.
        </Text>
      )}
    </Flex>
  );
};

hubspot.extend(() => <ShockAndAweCard />);
```
